# HerbaScope - Model Improvement Journey

How species-classification accuracy went from **88.9% to 97.2% on the test set** (and from
**87.5% to 92.0% in grouped cross-validation**) without training or fine-tuning a neural network,
what we tried, what failed, and what the numbers do and do not show. Every number below is copied
from a generated log in [`reports/`](reports/); the logs are regenerated by the commands at the
end of this document.

---

| **Best within budget** | H2 | + 588 px | **92.0%** | **97.2% (70/72)** | v4 |

- **Test accuracy passed 90% at E1 and 95% at F2.** The final recipe misclassifies 2 of 72 test
  images.
- **Cross-validated accuracy passed 90% at F2 and reached 92.0%.** It did not reach 95%; section 6
  shows where the remaining errors are and why a different embedding recipe is unlikely to remove
  them.
- The model that makes the prediction is still a **logistic regression with 1,537 parameters**. All
  of the improvement came from *how* we read features out of the frozen DINOv2 encoder.

## 2. The rules we set before touching the model

Plain language: the test set has only 72 images, so one image is worth 1.4 percentage points.
If we tried many ideas and kept whichever scored best on test, we would be choosing the idea that
happened to suit those 72 images, and the reported accuracy would be inflated. So we fixed the
rules first and wrote every idea down, in git, *before* running it.

| Rule | Why |
|---|---|
| **Pre-registration.** Each phase is a ladder file (`ml/configs/experiments-v*.json`) committed before it runs: a hypothesis per rung, the metric, the adoption rule and a latency budget. | The rule, not the result, chooses the model. Commits prove the order. |
| **Metric: grouped, stratified 5-fold cross-validation** on train + validation (415 images). Near-duplicate groups never straddle folds. | Every development image is scored by a model that never saw it or its near-copies: 415 judgements instead of 72. |
| **Adoption:** a rung is kept only if CV accuracy rises (or ties with lower log-loss), and one image encodes in ≤ 3 s. | A screening tool is interactive; a slower, more accurate model must not win by default. |
| **Test and held-out results are reported, never used to decide.** | Keeps them honest estimates. |
| **Rungs run in order**, each on top of the best recipe so far. | Each change is measured against the recipe it would actually modify. |
| **One implementation.** Experiments pool cached encoder tokens with the production functions. | The embedding that was measured is the one that ships. |

Registration commits: phase 1 `f75023b`, phase 2 `5a2d20c`, phase 3 `a58d8aa`, phase 4 `9f46ef5`.
Phases 2–4 were designed after seeing the previous phase's results, and each ladder's objective
says so.

## 4. Phase by phase

### Phase 1 - cheap, well-known levers
- **Orientation (E1, adopted).** A micrograph has no "right way up", so each of its eight
  rotations and reflections is a real observation of the same specimen. Training on all of them
  and averaging them at inference is free, label-preserving augmentation. CV 87.5% → 88.2%.
- **Patch tokens (E2, rejected).** Test rose to 68/72, but CV fell back to 87.5%. This was the
  first test of the protocol: on test alone we would have kept it.
- **Resolution (E3, adopted).** The 300 px micrographs were being shrunk to 224 px, so small
  structures (stomata, crystals) covered few 14 px patches. At 308 px: CV 89.4%.
- **Bigger encoders (E4 rejected, E5 reference).** ViT-B/14 *lowered* CV to 88.7% and took 3.7 s
  per image. More parameters did not read these micrographs better.

### Phase 2 - read finer detail without a bigger model
- **Multi-block CLS (F1, adopted).** The final CLS token is the most abstract summary; the CLS
  tokens of earlier blocks keep mid-level structure such as cell outlines. Concatenating the last
  four is DINOv2's own linear-probe recipe. CV 89.9%, and held-out accuracy rose from 57 to 62
  of 104.
- **448 px with four rotations (F2, adopted).** Eight views at 448 px would take about 3.1 s, over
  the budget, so the rung traded the four reflections for resolution. **CV 90.6%, test 95.8%**:
  both first milestones. Promoted to release v2.

### Phase 3 - more views or more resolution?
- **Six views (G1, rejected).** Test rose to 70/72, but CV fell to 90.4%: the second time the
  protocol refused a test-set improvement.
- **518 px (G2, adopted).** CV 91.6%. Promoted to release v3.

### Phase 4 - texture, and the last resolution step within budget
- **Patch texture at high resolution (H1, rejected).** An error review suggested that the remaining
  errors were texture-level, so we retried patch-token pooling at 518 px. CV fell to 89.6%. Patch
  pooling failed at both resolutions.
- **588 px (H2, adopted).** CV 92.0% (33 out-of-fold errors instead of 35), **test 97.2%**,
  2.65 s per image, close to the 3 s budget.
- **588 px with two rotations (H3, rejected).** Faster (1.3 s) but CV 91.1%: the views matter.

## 5. Challenges, and how we handled them

| Challenge | What happened | How we handled it |
|---|---|---|
| **A tiny test set** | 72 images; one image = 1.4 points. | Selection by grouped CV over 415 images; test only reported. |
| **The temptation of test gains** | E2 and G1 raised test accuracy but lowered CV. | Rejected both, as the registered rule required. |
| **Accuracy vs. speed** | Eight views at 448 px or ViT-B cost over 3 s per image. | A registered 3 s latency budget; over-budget rungs are reported as references only. |
| **Bigger models did not help** | ViT-B/14 lowered CV. | Invested in resolution and pooling of the small model instead. |
| **Diminishing returns** | 90.6 → 91.6 → 92.0: the last step is 2 images. | Stopped at the latency budget: a full analysis takes 2.8 s, and the next resolution step with four views extrapolates to about 3.0 s of encoding alone. |
| **Accuracy did not transfer to held-out material** | Held-out known-material accuracy only moved 49.0% → 57.7%. | Reported as the dataset's species/fragment-type confound, not tuned away. || **The decision layer did not follow the classifier** | PASS counts swung between releases (section 7). | Reported per release; thresholds never re-tuned on test data. |
| **Compute on a laptop CPU** | Each new resolution means re-encoding every split (up to ~1 h). | Token features cached per backbone and resolution; pooling and view rungs reuse the cache. |
| **Phases designed after results** | Only phase 1 was planned blind. | Every later ladder is registered before it runs and states that it followed earlier results. |

## 6. Why cross-validation stopped at 92%

Every log records where the out-of-fold errors fall, per fragment type. Comparing the starting
point with the final recipe:

| Fragment type | Class | Development images | Errors, E0 | Errors, H2 |
|---|---|---|---|---|
| epidermis atas (upper epidermis) | sirih | 42 | 13 | 11 |
| epidermis bawah dengan idioblas berupa sel minyak (lower epidermis, oil cells) | sirih | 42 | 9 | 7 |
| epidermis atas dan kristal kalsium oksalat bentuk prisma (upper epidermis, crystals) | sirih_merah | 61 | 12 | 5 |
| epidermis atas dengan stomata (upper epidermis, stomata) | sirih_merah | 57 | 10 | 4 |
| epidermis bawah dengan stomata dan idioblas berupa sel minyak | sirih_merah | 54 | 5 | 2 |
| sklerenkim (sclerenchyma) | sirih | 82 | 3 | 4 |
| rambut penutup (covering trichomes) | sirih | 77 | 0 | 0 |
| **Total** | | **415** | **52** | **33** |

- **The improvement happened where the hypothesis said it would.** Preparations defined by small
  visible structures (crystals, stomata) went from 27 errors to 11 as resolution and multi-block
  pooling let the encoder resolve those structures.
- **Two fragment types did not move.** Sirih upper epidermis and lower epidermis with oil cells
  are 20% of the development images but 55% of the remaining errors (18 of 33). Upper epidermis
  never dropped below 11 errors in any rung.
- **Why.** Visual review of the most confident errors shows plain polygonal epidermal cells with no
  visible stomate, crystal or oil cell: the structures that distinguish the labelled preparations
  are simply not in the frame. In Mikrobat,
species and fragment type are fully confounded (no fragment type occurs under both species), so a
crop of plain upper epidermis carries little species information. Resolution, views and pooling
cannot add structure that the crop does not contain. The route to higher accuracy is **data**:
more specimens per fragment type, the same fragment types under both species, and specimen
identifiers.

## 7. What changed for users: the releases

Classification accuracy is only one input to a screening decision. Each adopted phase was promoted
to a full release, rebuilt, recalibrated and evaluated:

| Release | CV accuracy | Test accuracy | Test passes (correct) | Held-out passes (correct) | DIMPSAR OOD rejected |
|---|---|---|---|---|---|
| v1 | 87.5% | 88.9% | 24 (24) | 52 (21) | 200/200 |
| v2 | 90.6% | 95.8% | 16 (15) | 17 (7) | 200/200 |
| v3 | 91.6% | 95.8% | 26 (26) | 34 (7) | 200/200 |
| v4 | 92.0% | 97.2% | 19 (18) | 20 (2) | 200/200 |

- **Out-of-distribution rejection never regressed**: every release rejected all 200 field
  photographs.
- **PRELIMINARY_PASS does not follow accuracy.** A pass requires all five nearest references to
  be the predicted species. The 40 references are re-selected by k-means in every new embedding
  space, so this agreement is a property of each release.
- **Held-out fragment types stay unsafe.** Material whose fragment type is absent from the
  reference library can pass with the wrong species in every release. Calibration only sees
  represented material, so no embedding recipe fixes this; the reference library must cover every
  fragment type to be screened.

## 8. Reproduce

```bash
python -m ml.experiments.run_experiments --config ml/configs/experiments-v1.json
python -m ml.experiments.run_experiments --config ml/configs/experiments-v2.json
python -m ml.experiments.run_experiments --config ml/configs/experiments-v3.json
python -m ml.experiments.run_experiments --config ml/configs/experiments-v4.json
python -m scripts.run_pipeline --from extract_embeddings   # rebuild the release in pipeline.json
```

Results are deterministic (fixed seed, pinned data and weights). Encoding times depend on the
machine; the reported ones were measured on an AMD Ryzen 7 7735HS laptop CPU.
